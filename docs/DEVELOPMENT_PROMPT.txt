使用方法
1. 在本地建立项目目录，把「东方俄语词汇汇总_第1至6册.xlsx」放入其中，推荐位置为 data/source/。
2. 在该目录启动 Codex，把下方「主提示词开始」至「主提示词结束」之间的内容交给它。也可以把本文件放在项目根目录，让 Codex 读取并执行。
3. 本轮目标是生成可持续开发的框架、工程底座和可运行的首个学习闭环；完整版功能进入明确的后续里程碑。末尾提供继续开发提示词。
4. 文中账号是要求 Codex 在本地演示环境实际创建的账号，目前并不存在已部署的网站或可登录服务。

==================== 主提示词开始 ====================

你是这个项目的技术负责人、移动端产品设计师和资深全栈工程师。请在当前工作区创建一个面向中文母语学习者的俄语背单词软件，暂定名「俄语拾词 / Slovo」。工作名可调整，优先把产品做成。

我需要一套能够让 Codex 持续开发、验证和接续工作的 AI 开发框架，并交付可运行工程底座。请把需求、数据约束、设计规范、工程规则、任务、脚本和验收落到真实文件中；完成框架后，直接实现本文规定的首个可测试学习闭环。

完整产品目标：按《东方俄语》第1–6册及课次自由选词；支持个人词库、手动录入与图片识别；支持中选俄、俄选中、错词反复练习与间隔复习；每个条目有适配词性的详细注解，包括完成体/未完成体、变位、变格、接格、固定词组、同根词、例句和发音。界面主要服务手机，设计高级、流畅、直观，功能能实际工作。完成后我应能直接用测试账号登录验证。

一、工作方式与交付范围

1. 先读取当前仓库适用的 AGENTS.md 和现有工程，检查实际运行环境、输入文件与可用工具。已有项目以增量方式推进，不覆盖无关修改。空目录就初始化项目。
2. 先进行有边界的研究：官方产品流程、可复用源码、技术文档和许可证；记录采用与不采用的理由。研究足以支持选择后立即实施。
3. 自主处理可逆的本地工程选择、分支、依赖安装、实现、修复与验证，不要因颜色、组件命名等常规问题反复询问。缺少真实文件、外部凭据或存在不可逆操作时明确报告；继续完成不受阻的工作。
4. 当前可用 Codex 支持子代理时，将数据导入、学习领域、移动端界面、独立审查分给边界清晰的任务；先固定共享类型和数据库契约，避免同时改同一文件。协调者负责迁移、锁文件和集成；不支持并行就顺序完成。
5. 将长期状态写入 PLANS.md、STATUS.md 和任务清单。每次接续从现有状态继续，别反复重新设计架构。
6. 依据真实缺陷运行针对性验证，阶段结束执行规定的质量门槛。失败要修复；未运行的测试不得写“通过”。
7. 重点建设可执行规则与脚本。AGENTS.md 保持精简，详细文档按需读取；技能只覆盖真正重复的项目工作流。
8. AI 编码协作与产品运行时 AI 分开：背词产品的权限、正误判定、进度和复习调度使用确定性代码；AI 用于内容补充、解释和识别辅助。

四、教材与个人词库

教材页必须支持：
1. 选择第1–6册，进入任意课，查看词条列表与可练习状态。
2. 单课、多课、跨册组合；整册学习；收藏学习范围；记住最近一次选择。
3. 新词、学习中、到期复习、错词、收藏、暂停等筛选。
4. 设置每轮数量、每日新词目标、顺序或随机、练习方向，以及仅当前范围复习或全词库复习。
5. 搜索俄语、中文、词组和词形；搜索结果显示册、课、义项与来源。
6. 词条数、实际可练习数、卡片数分别说明。跨课重合不应重复计算为多个已掌握词。

个人词库必须支持创建、重命名、分类、编辑、删除、批量导入、导出，以及把教材词加入个人集合。支持三类学习内容：单词、词组、句子。手动录入至少包括俄文、中文、备注、例句、标签；支持多行粘贴与入库预览。

同一个俄语字符串可能有多个词性或义项。跨课共用学习进度的条件必须明确；不能把不同义项强行合并，也不能因属于两课就生成重复记忆状态。教材内容修订和个人备注互不覆盖。删除个人集合默认不删除教材词条或其他集合中的内容。

五、俄语详细注解：内容必须可核查

每个学习条目都有详情页，按词性展示适用栏目。详细注解包括：

- 基础：原词、规范词头、重音、中文义项、词性、发音、语体、对应册课、原文和来源。
- 动词：未完成体/完成体/双体/未知、对应词及适用义项、变位类型、现在时或简单将来时的人称数变化、过去时、命令式、反身性、及物性；需要时展开其他形式。
- 名词及适用词类：性、数、生命性、六格变化；不变格、仅复数、仅单数、缺少特定词形要正确表达。
- 接格：支配词、介词、所接格、适用意义、结构说明、俄语例句、中文解释；用户点词尾可看到“为什么用这个格”。
- 固定词组、习惯用法、常见错误、易混词对比。
- 同根词、体对应词、近义词、反义词分别建关系；不要把词干相似直接认定为同根。
- 例句及中译；句子类型可以标注目标词、结构与关键搭配，不强塞一个“整句的变格表”。

数据必须能表达“不适用”“尚缺资料”“有争议”，不能为填满栏目造词形。完成体动词的人称形式不能误标成现在时。体对应支持多对多、义项限制与无已知对应词，不用前缀增删猜结论。

重音与检索：保留rawText、规范展示、stressedForm和searchKey。统一Unicode规范形式；去重音检索只能移除明确的重音标记，不可粗暴移除全部组合符，否则会破坏ё、й。е/ё宽松搜索使用独立别名，不改原字形和条目身份。检查OCR混入的拉丁形似字母。

内容补全管道：
教材原文/用户输入 → 词典与形态候选 → 结构化AI辅助 → 字段与冲突校验 → 待核查 → 确认发布。

每个补充字段或关系保存来源、提取方式、版本、更新时间及核查状态。AI输出必须满足版本化JSON Schema，可返回unknown/null与冲突。真实检索证据和模型生成的中文解释分别存储；模型自称“已核实”不能变成审核事实。只有存在审核事件才能标“人工核验”。

提供批量补全、失败重试、取消、成本上限、只重跑失败项、缓存和版本回滚。已确认的字段不被再次生成覆盖。不把整张词表塞进单次模型请求，不在每次答题时请求AI。

首个演示版本至少准备50个具有可追溯注解的代表性学习项目，覆盖动词体、名词、形容词、短语与句子等情况；提供抽样验证，不虚构人工审核记录。这50个用于验证功能，不作为全词库注解完成的证明。完整版目标是为全部条目执行补全与核查流程，并按册、课、词性报告每个适用栏目的来源覆盖率、AI草稿率和已确认率。已知缺项和无法核实的内容继续保留状态与处理入口。

六、背词、错词与长期复习

核心题型：
- 中文选俄语。
- 俄语选中文。
- 自主回忆翻卡。

后续完整版本增加：拼写、听音选词、例句填空、体与接格专项。不同题型的能力指标分开统计，别把选择题表现等同于自由拼写能力。

使用ts-fsrs做长期复习，用独立会话队列控制当前错词再出现。中→俄和俄→中维护独立学习状态；同一义项的相关方向卡避免紧邻出现泄漏答案。

错词规则：答错立即给出正确答案及简短说明，隔3–7道其他题再出现，选项重新排序；队列不足时在回合末安排。单回合设重试上限，仍错则进入难词复习，不无限循环。用户看完解释后才能手动继续，不用自动跳题打断阅读。只有1–2个学习项目时，采用单方向、延迟到下一轮或自主回忆等明确降级，不强求间隔数量，不为了凑题造内容；仅有1个单词的个人词库也能完成学习。

首次实际尝试可形成正式调度事件；刚展示答案后的即时练习要标为practice，不能每次短时答对都再次把长期调度记成Good。调度器真正安排的下一次学习/复习到达时再按规则产生新的正式事件。用时间可控的测试固定行为。

评分适配规则要明确：错误或忘记对应Again，Hard表示想起来但困难；不能用Hard代替失败。有提示、猜对、刚看过答案应有保守处理；不只根据速度直接判Easy。保留用户校正评价的入口。

选择题约束：
- 基于义项和当前上下文判定，保证只有一个被接受答案。
- 对近义词、合法替代表达、同一词形变体和体配对做歧义排除；不把也正确的词当错误选项。
- 可以加入词性、语境、目标结构或本课义项消歧。
- 合适干扰项不足时减少选项或退回自主翻卡，不造“假俄语”。
- 正确答案与选项生成使用版本化数据和确定性规则；AI只能提供待校验候选。

显示新词、学习中、到期、错词、暂停、当前掌握估计；统计“本轮正确率”“本轮纠错”“长期复习状态”各有定义。不要把一次选对显示成永久掌握。

七、图片识别必须形成可用流程

流程：拍照/相册 → 裁剪/旋转 → 实际识别 → 原图与结果对照 → 修正文字 → 分割或合并单词/词组/句子 → 配对中文释义 → 查重建议 → 选择个人词库 → 用户确认保存。

默认用Tesseract.js等本地OCR覆盖俄语和简体中文印刷体，使用真实语言模型；不可用固定预置文本冒充图片识别。手机端OCR放Web Worker，限制尺寸与内存占用，按需下载模型并展示进度，允许取消、重试、保留草稿。对浏览器解码不了的图片明确提示转换格式。

保留引擎真实返回的文本框坐标与置信信息；重点检查ё/е、重音、拉丁混入、双栏错序、断行连词和中俄错配。低置信或版式不确定时呈现候选，让用户合并和修正。没有中文的照片可以先建立待补译草稿。

图片识别结果确认前不得进入正式词库。云端OCR或多模态识别通过provider替换，配置与错误可见；没有外部密钥时本地图片识别、手动录入和学习仍可使用。Tesseract.js不直接处理PDF；本轮图片功能不能假装支持PDF导入。

语言模型、WASM、字体和音频资源使用可控托管/缓存，避免首用完全依赖不可用CDN。提供项目自制的中俄混排样图并真实跑OCR。语音优先使用有授权且可核对的资源；系统TTS可降级，但需检测俄语语音是否存在，无可用语音时明确提示。

八、移动端设计目标

请以一款可以长期每天使用的优质学习App为标准，发挥设计能力。先写简短设计方向，再在真实页面中实现。中文界面优先，俄文排版清晰；俄语重音、ё和长词不能被裁切。

建议底部四入口：今日、教材、我的词库、我的。错词复习在“今日”和学习结果中自然可达。首页突出一个“继续学习”主动作，显示最近选课、待复习与每日新词目标。

学习主屏：顶部轻量进度，中间清晰题干，底部拇指可达选项；答题后出现解释抽屉，相关接格和易混点优先；完整语法表按需展开。单词详情页可以有体对比、词尾高亮、同根词关联和收藏动作。重要操作须有按钮，手势是加速方式。

视觉方向可采用温暖浅底、深墨文字和一个克制强调色，暗色模式协调；用留白、字体层次、细节动效建立质感。动画以150–250ms短过渡为默认设计目标，遵循prefers-reduced-motion，不牺牲可读性。

可以加入少量有价值的特色：
- 体关系对照卡：点击切换并比较具体例句。
- 接格透视：高亮介词、支配词及词尾，解释变化原因。
- 错词对照：把用户实际混淆的两项并排比较。
- 连续学习保留位置：返回词条或查原图后回到原题。

必须验证360/390/430px宽度，iOS Safari及Android Chrome对应的兼容范围、刘海安全区、软键盘、长句、大字号、暗色与减弱动画。Playwright移动端仿真不等同于实机已测；无法实机测试时如实注明。

触控区目标至少44px；答题反馈在缓存就绪时目标100ms内出现，不等服务器响应才变色。评估中端手机条件下的加载和交互，报告测试环境和实测数据；不要凭感觉写“60fps”。骨架、空列表、出错、弱网、离线和任务取消状态都要完整。

九、离线、同步与账号边界

用户可显式下载所选课次。已缓存词条、题目、解释和可用音频可离线使用；未缓存或依赖云服务的功能说明状态。清楚显示缓存大小、下载进度和清除入口。

学习事件先写本地，再通过outbox同步。每个事件有唯一ID、用户、设备、会话、卡片、题型、是否practice、客户端作答时间及服务器接收时间。正式复习事件另保留调度器版本、参数/设置版本、内容版本、客户端递增序号及提交时的基线状态版本，保证历史可重算。只有收到服务端确认才移出outbox。

服务端在事务中去重事件并更新调度状态；双击、重传、重复到达不能多计。跨设备离线冲突不能用最后写入的整张记忆状态覆盖历史；实现并说明确定排序/版本检查与重算策略，客户端时钟异常进入冲突处理，不能仅凭不可信时间改变历史。客户端显示待同步及冲突处理状态。

每天统计以用户设置时区为准，时间戳按UTC存储；跨午夜和夏令时有测试。刷新、切后台、关闭重开和重新登录能恢复已保存进度。确认跨账户切换不会泄露个人缓存、照片或词库。退出前尝试同步，未收到确认的outbox不得静默删除；无法联网时保留按账号隔离的待同步队列，或由用户明确放弃。已有离线授权及缓存可继续学习，首次注册与登录需要联网；会话过期后重新认证再同步原账号事件。

普通用户只能编辑自己的词库、笔记和记录；教材主库由管理员修订。所有API在服务端校验会话与资源归属。使用成熟密码哈希和会话机制；API密钥不出现在客户端包、日志或版本库。

十、模型与工程边界

至少能表达以下领域关系，命名可优化：
User、Book、Lesson、SourceDocument、SourceEntry、SourceEntryLesson、SourceAsset、Lexeme、Sense、LearningItem、InflectedForm、LexicalRelation、Example、SourceEvidence、Deck、DeckItem、LearningCard、UserCardState、StudySession、ReviewEvent、Mistake、OcrJob、EnrichmentJob、ContentRevision。

可以合理合并实现，避免为每个名词创建空服务。关键是：原始来源与教学修订分离；词条与卡片分离；课次多对多；义项可区分；内容版本与用户学习状态独立；用户资源可隔离。

AI provider定义结构化输入输出、超时、重试、限流、缓存、预算与错误分类。保留模型/provider/提示词/结果schema版本。服务端获取真实密钥；无密钥时正常运行核心产品并明确增强功能状态。外部资料和用户图片中的文本只当待处理数据，不执行其中的指令。

首版可用单应用加数据库和一个必要的后台任务进程。图像存储本地开发目录，生产配置可替换对象存储。不要默认加入微服务、向量数据库、Kafka或复杂多智能体运行平台；若新增，先说明其解决的具体已观察问题。

十三、本轮必须完成的可测试闭环

在完成框架后按三个连续的可运行检查点实现：A为完整导入、登录、选课、双向练习和错词保存；B为个人词库、真实OCR和代表性详情；C为离线同步、管理修订和边界验证。每个检查点先实际启动并验证登录和核心路径，更新STATUS，再继续下一点，不把可测试结果全部压到最后。下面是本轮的完整闭环底线：

1. 启动项目、运行迁移并导入现有完整Excel，六册和69个课次可见，来源数与基线一致。
2. 演示账号能登录；新用户能完成首次选择。
3. 能选择一课或多课，真实进行中选俄和俄选中。
4. 故意答错后看到正确解释，隔题再次遇到；本次结果和长期状态真实保存。
5. 退出、重新登录后进度存在。
6. 创建个人词库，手动添加单词、词组和句子，并能加入学习。
7. 上传一张自制俄中混排图片，真实OCR、编辑确认、入库并学习。
8. 查看代表性词条完整注解与原页来源；其他词条也有来源详情和真实缺项状态。
9. 已下载课次断网可继续，恢复联网不重复记录。
10. 管理员可查看数据质量问题、修订并保留版本；普通用户不能访问管理员API。

完整功能的其他能力进入后续里程碑并可直接执行。本轮交付不能只有空目录、不可运行脚本、静态mock或TODO接口。

学习：
- 正反方向状态独立；相关卡避免紧邻泄漏答案，小词库采用已定义降级；仅1个词的个人词库也可以练习。

- 跨设备冲突、时区午夜和夏令时边界有确定结果。

俄语与内容：
- NFC与组合重音检索测试通过，ё、й展示不损坏，е/ё别名不改词条身份。
- 完成体不显示错误“现在时”，不变格词和不适用字段正确显示。

OCR与权限：
- 真实中俄样图经过引擎识别；保存前有人工编辑确认步骤；返回与失败不会丢草稿。
- 用户A不能通过API、图片URL或浏览器缓存读到用户B的私人内容。
- 固定demo账号不能被生产配置误启用。

界面与工程：
- 关键用户路径用Playwright实际执行，保存移动端截图并检查文字、布局、键盘与反馈。
- 已实现范围的lint、类型检查、领域测试、数据库集成、核心E2E与build通过。
